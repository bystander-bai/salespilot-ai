## 3. 主要测试内容与结果

### 3.1 账号登录与访问权限

| 测试场景         | 预期及实际结果                                                             |
| ---------------- | -------------------------------------------------------------------------- |
| 登录、刷新与注销 | 正确账号可进入工作台，刷新后保持登录；注销后当前账号接口返回 401，符合预期 |
| 登录表单反馈     | 空账号、错误密码均有提示；密码显隐切换和账号帮助入口可正常使用             |
| 角色权限         | 销售不能管理账号，越权请求返回 403；最后一个管理员不能被停用或降级         |
| 账号维护         | 管理员可创建账号和重置密码；重置后原登录失效，停用账号不能再次登录         |
| 来源校验         | 合法同源代理或配置来源可登录；非法来源、跨站写入及伪造转发头被拒绝         |

### 3.2 订单、库存与私有会话

| 测试场景       | 预期及实际结果                                                               |
| -------------- | ---------------------------------------------------------------------------- |
| 订单与库存联动 | 对话返回订单卡片，详情可继续查询指定商品的各仓库存，结果对应正确商品         |
| 历史会话管理   | 可搜索本人会话、重命名并重新打开；刷新后消息及结果卡片可恢复                 |
| 私有会话隔离   | 其他成员及管理员访问他人会话返回 404，搜索不会返回他人的消息                 |
| 重复请求       | 同一请求号和相同内容返回已有结果，不重复新增消息；更换内容复用请求号返回 409 |
| 待补参数恢复   | 查询库存缺参时先追问；关闭并重新创建应用后，补充仓库和商品仍能完成查询       |
| 旧数据迁移     | 构造的旧工单可在升级后查询，未记录的商品、申请人及首次响应时间不被补造       |

### 3.3 售后申请与工单处理

| 测试场景       | 预期及实际结果                                                               |
| -------------- | ---------------------------------------------------------------------------- |
| 草稿与确认提交 | 对话生成 `ticketDraft` 时不新增工单；用户核对并确认提交后才创建工单          |
| 订单与商品校验 | 不符合售后条件的订单、非本订单商品、零数量、超量及重复商品均被拒绝           |
| 幂等提交       | 相同申请重复提交返回原工单；修改内容复用幂等键返回冲突，应用重新创建后仍有效 |
| 状态流转       | 待处理→处理中→已解决→已关闭可完成；解决时需填写说明，非法状态操作被拒绝      |
| 分配与转派     | 管理员可分配或转派给符合要求的负责人，转派后原负责人不能继续越权操作         |
| 数量占用与释放 | 有效申请占用可申请数量，取消后释放；并发申请不能超过可申请数量               |
| 并发领取与事务 | 两人竞争领取仅一方成功；多商品校验失败时，不留下新增工单或创建日志           |
| 删除来源会话   | 删除会话后工单及处理记录仍保留，来源会话关联按规则清除                       |

### 3.4 异常恢复、执行链路与页面交互

执行链路能够区分等待补参、调用中、失败、重试成功和草稿待确认。首次失败后重试成功时仍保留失败记录；缺少历史事件时不补造调用参数或成功结论。

通过真实 HTTP 连接断开 SSE 后，模拟模型请求被中止，服务端保存中断记录，会话可重新读取；应用重新创建后，遗留运行被标记为中断，原请求不会自动重跑。这里验证的是应用恢复逻辑，没有模拟服务器断电。

接口测试验证了生成中同会话请求和删除操作受到保护；浏览器测试验证了订单列表刷新失败时保留上次成功加载的数据并显示提示。

桌面布局覆盖 1920×1080、1440×900、1366×768、1280×800 和 1024×768，检查页面无横向溢出且发送按钮位于可视区域。主业务闭环测试中未出现页面运行异常。

## 4. 关键业务联调流程

### 4.1 订单查询到售后处理闭环

1. **销售查询订单**：登录后输入“查询订单 SO202611003”，页面显示订单结果卡片；刷新页面后结果仍可查看。
2. **详情与库存联动**：打开订单详情，选择查询商品库存，展示该商品的跨仓库存；返回时可继续查看原订单。
3. **售后核对与提交**：进入售后申请，填写商品数量和问题描述，先核对申请，再点击“确认提交”，随后显示新工单及待处理状态。
4. **客服处理**：独立浏览器上下文以客服身份打开工单，领取后填写解决说明，标记已解决并关闭，形成完整处理流程。
5. **销售跟踪结果**：销售刷新工单详情后看到已关闭状态，再通过对话查询工单进度，结果与详情一致。

该流程验证了页面交互、前端代理、业务接口和数据库读写之间的衔接，以及不同角色对同一业务记录的协作。工单关闭仅代表本系统处理流程结束，不涉及实际退款、收货或库存扣减。

### 4.2 管理员分配与异常反馈

管理员进入待领取工单，未选择负责人时不能提交分配；选择有效负责人后完成分配，再转派给另一负责人，详情同步展示新的负责人。订单列表支持排序和搜索；人为中断刷新请求后，页面显示更新失败提示，并保留原有列表内容。

### 4.3 会话与执行过程展示

自然语言申请维修先生成“尚未提交”的售后草稿；历史会话可以按消息搜索和重命名。打开指定会话后可查看对应执行链路，在订单和库存消息之间切换时，工具名称及结果随所选消息更新，未将历史调用混作当前调用。

上述浏览器联调流程均已通过。

## 5. 联调问题及处理情况

默认 Playwright 启动时缺少匹配的无头浏览器依赖，改用已有 Chromium 后仍出现启动错误。定位到失败发生于浏览器启动阶段，尚未执行页面业务操作。

随后通过 `PLAYWRIGHT_CHANNEL=chrome` 改用本机 Chrome，5 项浏览器测试全部通过。该处理解决了本次联调执行问题；默认浏览器依赖及 Chromium 启动原因仍需在需要使用该环境时单独处理。

## 6. 测试结论与后续建议

本次 45 项自动化测试及完整构建均通过，已覆盖的本地演示模式下，订单和库存查询、售后确认提交、多人协同处理、私有会话和恢复流程符合测试预期。少量并发竞争用例验证了对应业务约束，不等同于系统已通过压力测试。

后续建议补充以下验证：

- **真实模型网关**：工具调用参数与结果回传、真实流式输出、超时和异常响应，以及自然语言理解效果。
- **部署与数据保障**：Docker、Nginx 代理、HTTPS 和生产环境启动，业务数据库副本上的升级核对及备份恢复演练。
- **性能与兼容性**：高并发、长时间运行、大数据量，以及其他浏览器和移动端的完整流程。
